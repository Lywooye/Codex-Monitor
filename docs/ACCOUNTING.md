# v0.4.0 统计口径

## Tokens 与轮次

优先读取 `token_usage_record`，按 `response_id` 去重，以 `turn_id` 汇总完整任务轮次。输入/输出与总量使用 Codex 原始字段；缓存输入包含在输入中，推理包含在输出中，不再次相加。

`compacted.compaction_response_id` 标记压缩请求，`latest_token_usage_record` 可以补足独立记录缺失的压缩用量。两种形式同时存在时只计一次。压缩量作为“已计入”的子项显示。压缩事件没有对应用量时显示缺口；不会从摘要长度猜 token，也无法补回服务端未写入本地日志的消耗。

原生记录与 `token_count` 同时存在时，该轮以原生记录为准。旧格式只累计递增的 `total_token_usage` 差值；重复快照为零。首条累计大于末次用量时，把前缀计入会话总数，但其轮次和时间未知，不参与额度归因。累计回退会警示可能漏计。旧格式没有原生压缩 usage 时无法保证完整计入压缩。

会话指同一个 thread ID。原生 fork 继承的其他 thread 记录不作为本聊天新消耗；独立子代理线程单独统计，不自动合并到父线程。旧格式缺少 thread/turn 标识时，分叉归属和轮次划分可靠性较低。

每轮最后一条普通助手消息显示整轮用量；进度消息不重复贴整轮标签。界面明确识别聊天后，先按轮次 ID 匹配，再允许唯一且足够长的文本前缀匹配。虚拟列表、重复回复、缺失标记时宁可不显示，也不按位置猜测。历史行中的“会话总计”是该会话当前总量，不是当时累计快照。

## 工具

按日志中 `call_id` 去重，显示每轮/会话次数、每种工具名称和已返回次数。返回只说明收到输出，不能推出成功；等待中的调用仍计入调用次数。不展示参数、文件内容或输出正文，也不为工具另加一份 tokens（模型读写工具上下文的消耗已经包含在 usage 中）。一个 `functions.exec` 包装多个内部操作时，只能显示日志实际公开的调用边界。

## 周额度：按观测区间分摊

使用 `rate_limits` 中 `window_minutes = 10080` 且 `limit_id = codex` 的账号级快照；每周窗口可能位于 primary 或 secondary。读取所有可访问的本地活动/归档会话，按账号与响应标识去重，UI 的最近会话数量限制不缩小分母。

相邻快照时间为 a、b，重置时间相同且占用不下降时：

```
该聊天在 (a,b] 内的额度分摊（百分点）
= 账号 used_percent(b) - used_percent(a)
  × 该聊天在 (a,b] 内的 tokens / 本机同账号全部聊天在 (a,b] 内的 tokens
```

这是用户选择的分摊口径，不是 OpenAI 提供的聊天账单或官方计费权重。模型、缓存、推理强度的额度权重未公开，不能由 tokens 精确换算订阅额度。

- 重置 deadline 变化，或同一 deadline 下占用下降，均开启新的统计段。后者也覆盖手动重置/观测回退，不能自动确认下降的原因。
- 跨重置的快照间隔不分摊。新周期第一个快照不是零基线；重置前最后快照到重置、重置到第一个快照之间的用量保留为缺口。
- 单轮横跨重置也按各模型调用时间分开，不把整轮压到结束所在周期。压缩请求同样参与分摊。
- 本周期显示该周期已观测到的分摊百分比；跨周期累计显示百分点，可超过 100。各周期明细列出 reset deadline 和统计段。
- 无快照、只有缺口而没有可分摊用量、当前快照已过期时显示未知。未覆盖 tokens 不填补为零。部分覆盖时，数值仅涵盖可观测区间，不外推未覆盖部分。
- 覆盖率 = 有有效前后快照的本聊天 tokens / 本聊天已知 tokens。它不是误差率、置信度或完整账号的覆盖率。
- 同时刻冲突快照、额度增长却没有本地 tokens、文件读取失败、账号标识缺失均显示提示。旧累计前缀没有时间，因此算在未覆盖 tokens 中。

其他设备/云端消耗、本机未记录的会话、取整、延迟和模型权重都会影响分摊；误差无法量化。不能承诺 ±x% 或“精确占用本周额度”。这套规则也不能恢复安装前没有写入日志的快照。

## 读取与兼容边界

索引只在进程内缓存必要的用量/工具元数据，不把聊天正文写入仓库或持久数据库。首次流式读取全部历史，后续增量读取；未完成的 JSONL 尾行留待下一次刷新。文件替换或缩短时重新解析。启动耗时随本机日志规模增长。

核对的本机版本为 ChatGPT/Codex Desktop 26.1007.21159（build 20052），内置 CLI 0.162.0-alpha.17.2。日志格式已通过真实样本核验；应用选择器与合成 DOM 验收通过。没有安装或注入真实客户端，因此不能把它表述为真实窗口端到端兼容保证。客户端升级后应重新验证日志字段和 DOM。
